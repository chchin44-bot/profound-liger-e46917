上傳到 GitHub · 圖說

v93i · 從解壓縮到網站更新，一步一步
只想讓網站更新的話，只有 index.html 是必要的。
其他檔案是工程用的，不影響網站，可以之後再說。

先看清楚：解壓縮後長這樣

taiwan-dashboard-v93i/ ├── index.html ← 產品本身（必上傳，要放在最外層） ├── README.md ├── github-upload-guide.html ← 你正在看的這一份 ├── tools/ ← 工程工具，5 個檔 │ ├── run-suite.sh │ ├── staleguard.sh │ ├── sync-source.sh │ ├── tests.manifest │ └── test-baseline.json └── tests/ ← 回歸測試，70 支 ├── invariants.mjs（等 9 支，含 v49） ├── r13/（58 支） └── scratch/（3 支）
要放進 GitHub 的是這個資料夾「裡面」的東西，不是資料夾本身。
也就是說，上傳完之後 index.html 要跟你 repo 原本的 index.html 在同一層。

步驟

1
打開你的 repo 首頁，會看到現有的檔案清單。
chchin44-bot / profound-liger-e46917
Add file ▾ Code ▾
📁 tools2 天前
📄 index.html2 天前
📄 README.md2 天前
2
點右上角的 Add file ▾，選 Upload files。
下拉選單裡有兩個選項：Create new file 和 Upload files。要點下面那個。
3
把解壓縮出來資料夾裡面的全部內容，一起拖進虛線框。
Upload files
把檔案拖到這裡
或 choose your files
GitHub 的網頁上傳支援整個資料夾一起拖，tools/ 和 tests/ 這兩層會自動保留， 不用一個一個放。
拖進去之後，畫面下方會列出所有要上傳的檔案（大約 74 個）。數量對不上不用緊張， 重點是 index.html 有在裡面。
4
往下捲，找到 Commit changes 那一塊，直接按綠色按鈕。
Commit changes
Add files via upload
Commit changes Cancel
上面那個訊息欄不用改，留預設的就好。
5
等 1～3 分鐘，GitHub Pages 要重新發布。

可以到 repo 的 Actions 分頁看：有一個打勾就是發布完了。不看也沒關係，等三分鐘再開網站就好。

6
驗收：打開網站 →

https://chchin44-bot.github.io/profound-liger-e46917/

一定要強制重新整理，不然看到的是瀏覽器存的舊版：

  • Windows：Ctrl + F5
  • Mac：Cmd + Shift + R
  • 手機：把分頁關掉再重開，或用無痕視窗

然後找頁面上的字級按鈕（標準／舒適／大字）， 它下面那行小字要寫 v93。有寫 v93 就是成功了。

驗收清單

  • repo 首頁看得到 index.html，日期是今天
  • repo 首頁看得到 tools 和 tests 兩個資料夾
  • 網站強制重新整理過
  • 字級按鈕下方那行小字寫著 v93

可能會遇到的狀況

網站沒變、還是舊的。
九成是瀏覽器快取。先確定強制重新整理過；還是舊的就用無痕視窗開一次。 無痕也是舊的，才回去看 Actions 有沒有跑完。
多了一個檔案，而不是覆蓋掉舊的。
表示檔名不一樣（例如變成 index (1).html）。 點進那個多出來的檔案 → 右上角垃圾桶圖示 → 刪掉 → 再重傳一次。 檔名必須一模一樣才會覆蓋。
絕對不要上傳的東西：
FinMind 的 Token、還有備份 JSON（裡面有你的成本價和持股）。 這個 repo 是公開的，任何人都看得到。這包裡沒有這兩樣，我掃描過了。
不想管工程檔也沒關係。
只傳 index.html 一個檔，網站一樣會更新。 tools/ 和 tests/ 是保險——開發環境已經被清空八次， 放進 GitHub 是為了下次不用重寫。
